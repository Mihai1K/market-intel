# market-intel

# ДАННЫЕ ВАЖНЕЕ КОДА

Если выбор стоит между «сделать красивый график» и «исследовать ещё один рынок» — всегда исследовать рынок. Единственный вопрос к каждой неделе: **«Сколько новых рынков исследовано?»** — не «какие фичи сделаны».

**Цель платформы: каждую неделю находить минимум одну бизнес-возможность, которую можно проверить за 7 дней и довести до первых денег быстрее чем за 30 дней.**

## KPI (поставлены 2026-07-13)

К **2026-08-13**: 10 рынков · 100+ компаний · 300+ болей · 50+ возможностей · 10–20 интервью · 5 лендингов · 5 рекламных тестов · 1–2 первые продажи.
К **2026-10-13**: 30 рынков · 1000+ компаний · 1000+ болей · 300 возможностей · 50+ экспериментов · минимум один продукт с подтверждённым спросом.
Исследования — конвейер Claude Code; интервью, лендинги, реклама и продажи — за основателем, результаты обязательно в data/experiments.json.

Платформа отвечает на 5 вопросов:
1. Где сильнее всего болит?
2. Кто уже платит за решение?
3. Что до сих пор делают вручную?
4. Что можно заменить AI?
5. Как быстро можно получить первых клиентов?

Это НЕ энциклопедия рынков. Критерий качества любого результата — помогает ли он принять решение и получить первые деньги, а не количество собранных полей.

## Архитектура

- Данные — JSON-файлы в git. Никаких БД, очередей, планировщиков, пока рынков меньше сотен.
- Дашборд — Next.js (App Router, Tailwind), читает `data/` на сервере. Тёмная тема.
- Исследования делает Claude Code: один рынок = одна исследовательская итерация.
- Итерация НЕ считается законченной после файлов и схем. Финал итерации — работающий дашборд, в котором можно сравнить возможности и выбрать одну для теста.

```
data/
  founder.json           # профиль основателя — против него считается Founder Fit
  schema/                # JSON Schema (документация структур)
  markets/<slug>/
    market.json          # объём (вилка), сегменты, buying power
    companies/*.json     # 1 компания = 1 файл
    pains.json           # база болей рынка
    workflows.json       # карта процессов отрасли
    opportunities.json   # идеи со скорингом
research/<slug>.md       # полный отчёт с цитатами и ссылками
scripts/validate.mjs     # валидатор — запускать после любого изменения data/
dashboard/               # Next.js
```

## Правила данных (нарушение = баг)

1. **Ни одной цифры без источника.** Каждое значимое число хранится только как факт-объект: `{ value, unit, period, source_name, source_url, retrieved_at, confidence: high|medium|low, method: reported|estimated|derived }`. `scripts/validate.mjs` ловит нарушения.
2. **Закрытые метрики не выдумывать.** LTV, CAC, retention, churn частных компаний не публикуются. Нет данных — нет поля. В отчётах писать: «нет в открытых источниках». Не подменять отсутствие данных оценкой.
3. **Объём рынка — только вилкой** и минимум из 2 независимых источников. Перепечатки одного отчёта = один источник.
4. **method:** `reported` — раскрыто самой компанией или госорганом; `estimated` — оценка третьей стороны; `derived` — вычислено нами, формула обязательна (`formula`).
5. **Финансы компаний (БФО ФНС) — доказательство ответа на вопрос «кто уже платит»** (растущая выручка игроков = в нише живые деньги), а не самоцель.
6. **Счётчик болей честный:** `mentions_found` — сколько упоминаний реально нашли, со ссылками и периодом поиска. Не «встречается повсюду».
7. **AI Readiness — только из наблюдаемых сигналов** (тексты вакансий, наличие онлайн-записи/API/чата на сайте), каждый сигнал с evidence_url. Нет сигнала — нет балла.
8. **Платные источники** (СПАРК, PitchBook, платный Statista/SimilarWeb) считать недоступными. **Не обходить** авторизацию, ограничения сайтов и антибот-защиту.
9. Отделять факт, расчёт и гипотезу. Гипотезы живут в opportunities и research, а не в полях компаний.
10. **История, не перезапись.** Если значение за уже записанный период изменилось (пересмотр отчётности, новая оценка) — старый факт НЕ удалять и НЕ править: пометить его `"superseded": true`, добавить новый факт с новым `retrieved_at`, причину пересмотра — в `note` и в research/changelog.md. Плюс git хранит всю историю: каждая итерация данных = отдельный коммит.
11. **Источник истины.** JSON в data/ никогда не редактируется вручную — только через исследовательские сессии Claude Code, каждая заканчивается коммитом с описанием источников. Число, появившееся вне этого процесса, считается недостоверным.
12. **Доказательства, не слова.** Итерация не считается проверенной без артефактов: `npm run artifacts` создаёт artifacts/<дата>/ с выводом валидатора, отчётом проверки ссылок (verify-links), HTTP-статусами страниц и скриншотами. «Я проверил» без этой папки — не проверка.

## Скоринг возможностей — две оси

- **Launch Score 0–100** — «можно ли заработать первые деньги за 30 дней»: острота боли (0.25), кто платит уже сейчас (0.2), достижимость ЛПР рекламой/прямыми продажами (0.2), реальность MVP за 7 дней (0.2), founder fit (0.15). Каждый компонент — оценка 0–10 с одним предложением обоснования.
- **Scale Score 0–100** — потолок: размер ниши (0.3), слабость конкурентов (0.3), moat (0.2), расширяемость (0.2).
- **Founder Fit — не число, а список** конкретных плюсов/минусов против `data/founder.json`.
- Сортировка везде по умолчанию — по Launch Score. Рынок 100 млн с продажей завтра бьёт рынок 1 млрд с циклом сделки 18 месяцев.

## Пять сущностей платформы

**Market → Company → Pain → Opportunity → Experiment.** Данные о рынках может собрать кто угодно; накопленные `data/experiments.json` (реальные расходы, лиды, продажи, CAC, выводы) и `data/decisions.json` (почему идея отклонена и когда к ней вернуться) — уникальный актив, который не воспроизводится. Каждое решение по возможности пишется в Decision Log с проверяемой причиной; каждый тест — в Experiment Database. Снимки скорингов (`node scripts/snapshot-scores.mjs`) копят Market Timeline — видно, как открываются и закрываются окна возможностей.

**Обратная связь (введена 2026-07-15):** цепочка «событие → возможность → лендинг → реклама → лиды → продажи → ROI» обязана прослеживаться по данным: событийная возможность содержит URL события-источника в why_now; каждый эксперимент ссылается на opportunity_id; итог эксперимента (ROI, вывод) — в experiments.json. Через несколько месяцев это ответит на вопрос: «какие ТИПЫ событий чаще всего приводят к реальным деньгам» — собственная статистика вместо чужой аналитики.

**Кросс-рыночные паттерны:** `data/patterns.json` — повторяющиеся типы возможностей (независимая проверка, CRM вместо Excel, услуга за фикс, комплаенс под ключ). Обновляется после каждого рынка и дайджестом. Паттерн в 4-5 независимых рынках = сигнал для продукта, переживающего отдельные рынки. Не сравнивать Launch Score между рынками как абсолют, пока рынков < 10-15 — рейтинг показывает лучшее среди исследованного.

**Кладбище продуктов (введено 2026-07-18, потребность повторилась в 4 исследованиях):** `data/graveyard.json` — умершие/ушедшие/поглощённые продукты рынков: что делали, почему не взлетело, что изменилось, возможна ли новая версия. Мёртвый продукт — такой же факт, как выручка живого.

**Три слоя движения рынка (рамка с 2026-07-18):** Structural Drivers (годы — определяют, ГДЕ строить; живут в market.json), Pain Points (месяцы — ЧТО продавать; pains.json), Events (недели — КОГДА и каким оффером; events + дайджест). Возможность высшего класса стоит на всех трёх слоях. В каждом новом исследовании помечать драйверы явно.

## Заморозка архитектуры (2026-07-13)

Архитектура заморожена до исследования 10–15 рынков. Новые функции — только если потребность повторилась минимум в трёх независимых исследованиях; все идеи — в BACKLOG.md, не в код. Главный актив дальше — данные и эксперименты, не интерфейс.

## Рабочий цикл

- Новый рынок: исследовать по этапам (скоуп → деньги/buying power → процессы → игроки → боли → возможности), записать в `data/markets/<slug>/` и `research/<slug>.md`, прогнать `npm run validate`, обновить дашборд, прогнать `npm run artifacts`, закоммитить.
- **После каждого рынка, ДО запуска следующего (правило от 2026-07-18):** обновить research/cross-market-insights.md (повторяющиеся проблемы/возможности, лучшие бизнес-модели по фактическим финансам, аномалии маржи с разбором «почему», чего ещё не встречалось), data/patterns.json и data/graveyard.json. Знания копятся в ширину, а не только в глубину.
- После каждого рынка глобальный рейтинг (/rating) обновляется автоматически — он агрегирует opportunities всех рынков и со временем становится главной страницей платформы.
- Еженедельно: обновить данные, пересчитать Launch Score, выбрать «Возможность недели» с готовым лендинг-оффером, каналами трафика, бюджетом и критерием успеха.

## Дорожная карта (принята 2026-07-13)

Не «рынок → идея → сервис», а: **15 рынков → ~100 возможностей → глобальный рейтинг → ТОП-10 → интервью с клиентами → лендинг → реклама → первые продажи → разработка.** Очередь рынков — в ROADMAP.md. Смысл: пока исследован один рынок, его лучшая возможность — лучшая из одного, а не лучшая вообще.
