# market-intel

**Цель платформы: каждую неделю находить минимум одну бизнес-возможность, которую можно проверить за 7 дней и довести до первых денег быстрее чем за 30 дней.**

Платформа отвечает на 5 вопросов:
1. Где сильнее всего болит?
2. Кто уже платит за решение?
3. Что до сих пор делают вручную?
4. Что можно заменить AI?
5. Как быстро можно получить первых клиентов?

Это НЕ энциклопедия рынков. Критерий качества любого результата — помогает ли он принять решение и получить первые деньги, а не количество собранных полей.

## Архитектура

- Данные — JSON-файлы в git. Никаких БД, очередей, планировщиков, пока рынков меньше сотен.
- Дашборд — Next.js (App Router, Tailwind), читает `data/` на сервере. Тёмная тема.
- Исследования делает Claude Code: один рынок = одна исследовательская итерация.
- Итерация НЕ считается законченной после файлов и схем. Финал итерации — работающий дашборд, в котором можно сравнить возможности и выбрать одну для теста.

```
data/
  founder.json           # профиль основателя — против него считается Founder Fit
  schema/                # JSON Schema (документация структур)
  markets/<slug>/
    market.json          # объём (вилка), сегменты, buying power
    companies/*.json     # 1 компания = 1 файл
    pains.json           # база болей рынка
    workflows.json       # карта процессов отрасли
    opportunities.json   # идеи со скорингом
research/<slug>.md       # полный отчёт с цитатами и ссылками
scripts/validate.mjs     # валидатор — запускать после любого изменения data/
dashboard/               # Next.js
```

## Правила данных (нарушение = баг)

1. **Ни одной цифры без источника.** Каждое значимое число хранится только как факт-объект: `{ value, unit, period, source_name, source_url, retrieved_at, confidence: high|medium|low, method: reported|estimated|derived }`. `scripts/validate.mjs` ловит нарушения.
2. **Закрытые метрики не выдумывать.** LTV, CAC, retention, churn частных компаний не публикуются. Нет данных — нет поля. В отчётах писать: «нет в открытых источниках». Не подменять отсутствие данных оценкой.
3. **Объём рынка — только вилкой** и минимум из 2 независимых источников. Перепечатки одного отчёта = один источник.
4. **method:** `reported` — раскрыто самой компанией или госорганом; `estimated` — оценка третьей стороны; `derived` — вычислено нами, формула обязательна (`formula`).
5. **Финансы компаний (БФО ФНС) — доказательство ответа на вопрос «кто уже платит»** (растущая выручка игроков = в нише живые деньги), а не самоцель.
6. **Счётчик болей честный:** `mentions_found` — сколько упоминаний реально нашли, со ссылками и периодом поиска. Не «встречается повсюду».
7. **AI Readiness — только из наблюдаемых сигналов** (тексты вакансий, наличие онлайн-записи/API/чата на сайте), каждый сигнал с evidence_url. Нет сигнала — нет балла.
8. **Платные источники** (СПАРК, PitchBook, платный Statista/SimilarWeb) считать недоступными. **Не обходить** авторизацию, ограничения сайтов и антибот-защиту.
9. Отделять факт, расчёт и гипотезу. Гипотезы живут в opportunities и research, а не в полях компаний.

## Источники для РФ (приоритет)

bo.nalog.ru (БФО ФНС) → api.hh.ru (открытый) → МСФО-отчёты публичных компаний → Smart Ranking, Data Insight, TAdviser, РБК Исследования, INFOLine → Коммерсантъ/РБК/Forbes. Зеркала данных ФНС: audit-it.ru, list-org.com, checko.ru (бесплатные страницы). vc.ru и Telegram — наводка, факты перепроверять.

## Скоринг возможностей — две оси

- **Launch Score 0–100** — «можно ли заработать первые деньги за 30 дней»: острота боли (0.25), кто платит уже сейчас (0.2), достижимость ЛПР рекламой/прямыми продажами (0.2), реальность MVP за 7 дней (0.2), founder fit (0.15). Каждый компонент — оценка 0–10 с одним предложением обоснования.
- **Scale Score 0–100** — потолок: размер ниши (0.3), слабость конкурентов (0.3), moat (0.2), расширяемость (0.2).
- **Founder Fit — не число, а список** конкретных плюсов/минусов против `data/founder.json`.
- Сортировка везде по умолчанию — по Launch Score. Рынок 100 млн с продажей завтра бьёт рынок 1 млрд с циклом сделки 18 месяцев.

## Рабочий цикл

- Новый рынок: исследовать по этапам (скоуп → деньги/buying power → процессы → игроки → боли → возможности), записать в `data/markets/<slug>/` и `research/<slug>.md`, прогнать `node scripts/validate.mjs`, пересобрать дашборд, показать результат.
- Еженедельно: обновить данные, пересчитать Launch Score, выбрать «Возможность недели» с готовым лендинг-оффером, каналами трафика, бюджетом и критерием успеха.
- Коммитить в git после каждой завершённой итерации данных.
